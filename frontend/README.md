# 🔁 Цепочка обмена

Frontend многостороннего сервиса обмена вещами. Пользователь публикует вещи, указывает интересующие категории и участвует в цепочках обмена с другими пользователями. Интерфейс покрывает весь путь от публикации объявления до передачи вещи в ПВЗ и подтверждения получения.

## ✨ Возможности

- регистрация, вход и восстановление сессии через HttpOnly cookie;
- просмотр и редактирование профиля пользователя;
- создание, редактирование и управление своими вещами;
- несколько фотографий вещи с галереей и полноэкранным просмотром;
- поиск и просмотр цепочек обмена;
- подтверждение или отказ от участия в обмене;
- выбор пункта выдачи и отслеживание этапов доставки;
- подтверждение получения вещи;
- чат участников внутри обмена и уведомления о событиях;
- отправка жалобы на сообщение другого участника;
- административная панель со статистикой, ПВЗ, жалобами, доставками и журналом действий;
- глобальная блокировка и разблокировка пользователей администратором.

## 🚀 Запуск проекта

### Требования

- Node.js 22+
- npm
- backend, доступный по адресу `http://localhost:8080` для локальной разработки

### Установка

```bash
git clone <repository-url>
cd frontend
npm ci
```

Создайте локальный файл окружения:

```bash
cp .env.example .env
```

Минимальная конфигурация:

```env
VITE_BASE_URL=/api
```

> В текущей конфигурации Vite запросы `/api/*` проксируются на `http://localhost:8080`, а префикс `/api` удаляется перед отправкой в backend.

Запустите frontend:

```bash
npm run dev
```

Приложение будет доступно по адресу `http://localhost:5173`.

## ⚙️ Особенности реализации

### API и авторизация

Все запросы проходят через единый Axios instance с `withCredentials: true`. Backend хранит JWT в HttpOnly cookie, поэтому токен не читается JavaScript-кодом и автоматически отправляется браузером с защищёнными запросами.

Ответы критичных API валидируются Zod-схемами до попадания в интерфейс. Это позволяет обнаруживать несовпадение frontend-контрактов и backend API раньше, чем некорректные данные попадут в компоненты.

### Работа с состоянием

- **TanStack React Query** отвечает за серверные данные, загрузку, кэширование, повторные запросы и обновление связанных данных после мутаций.
- **Redux Toolkit** используется для клиентского состояния авторизации.
- После действий, меняющих обмен, жалобу, ПВЗ или административную статистику, связанные query инвалидируются вместо ручного синхронизирования нескольких копий состояния.

### Цепочка обмена

Frontend поддерживает полный набор состояний обмена:

`proposed → confirmed → delivering → delivered → completed`

Отмена переводит обмен в `cancelled`.

На этапах передачи пользователь выбирает ПВЗ, следит за состоянием цепочки и после завершения доставки подтверждает получение. Для актуальных этапов используются повторные запросы, поэтому изменения состояния могут появляться без ручного обновления страницы.

### Административная панель

Админка организована секциями в рамках одной страницы:

- **Статистика** — пользователи, вещи, ПВЗ и обмены по статусам;
- **Завершение доставки** — очередь обменов в `delivering` и перевод в `delivered`;
- **Пункты выдачи** — создание, просмотр, редактирование и удаление ПВЗ;
- **Жалобы пользователей** — очередь модерации, карточка жалобы, переписка и решение;
- **История действий** — audit log с фильтрами и пагинацией.

В профиле пользователя администратор может просматривать его активные обмены, отменять допустимые обмены и выполнять глобальную блокировку/разблокировку через подтверждающий popup.

### UI и стили

- страницы загружаются через `React.lazy` + `Suspense`;
- стили компонентов изолированы через SCSS Modules;

### Production

Production image собирается в два этапа:

1. Node.js собирает приложение через `npm run build`;
2. Caddy раздаёт содержимое `dist` и проксирует API-запросы в backend.

Caddy также настроен на SPA fallback, поэтому прямое открытие клиентских маршрутов и обновление страницы не приводят к 404.

### Ключевые этапы, отражённые в текущей версии

1. базовая маршрутизация, авторизация и профили пользователей;
2. объявления, категории и управление своими вещами;
3. цепочки обмена и решения участников;
4. чат обмена и системные события;
5. интеграция ПВЗ;
6. подтверждение получения и завершение обмена;
7. жалобы пользователей и инструменты модерации;
8. административная статистика, управление ПВЗ и обменами;
9. audit log и глобальная блокировка пользователей;
10. унификация UI, адаптивных стилей и структуры Layout.
