# Цепочка обмена

Frontend сервиса многостороннего обмена вещами. Пользователь публикует вещь, указывает, что хочет получить, а сервис подбирает замкнутую цепочку из нескольких участников. Интерфейс сопровождает обмен от создания объявления и подтверждения участия до передачи через пункт выдачи, получения вещи и взаимной оценки.

## Что реализовано

### Пользовательская часть

- публичный лендинг с описанием сервиса;
- регистрация, вход, выход и восстановление сессии;
- просмотр и редактирование профиля, аватар, прогресс и отзывы;
- личные блокировки пользователей;
- лента доступных предложений и просмотр чужих профилей;
- создание, редактирование и удаление объявлений;
- загрузка нескольких фотографий, галерея и полноэкранный просмотр;
- управление участием вещи в поиске и выбором пункта выдачи;
- фильтры подбора цепочки: длина, минимальный рейтинг и приоритет надёжных участников;
- AI-помощник для подготовки названия, описания и категории объявления;
- просмотр цепочек, подтверждение или отказ от участия;
- отслеживание этапов обмена и подтверждение получения;
- чат участников, системные события, счётчик непрочитанных сообщений;
- жалобы на сообщения участников;
- уведомления с отдельной страницей, пагинацией и массовой отметкой прочитанного;
- оценка партнёра после завершения обмена;
- обращения в поддержку: треды, чат, быстрые подсказки и закрытие обращения.

### Уми и знакомство с интерфейсом

В приложение встроен интерактивный маскот Уми на SVG и CSS-анимациях. Он реагирует на действия и состояния интерфейса, помогает новым пользователям пройти семишаговое знакомство и меняет внешний вид по мере роста уровня. Прогресс знакомства хранится в `localStorage` отдельно для каждого пользователя, а уровень рассчитывается по числу завершённых обменов.

Подробности реализации собраны в [`MASCOT.md`](./MASCOT.md).

### Административная панель

- статистика сервиса и обменов;
- очередь доставок и перевод обмена в статус `delivered`;
- создание, редактирование и удаление пунктов выдачи;
- модерация жалоб с просмотром связанной переписки;
- AI-антискам: очередь подозрений, категории риска, доказательства и решение администратора;
- очередь обращений в поддержку, назначение ответственного и ответы пользователям;
- просмотр обменов пользователя и отмена допустимых обменов;
- глобальная блокировка и разблокировка пользователей;
- журнал действий администраторов с фильтрами и пагинацией.

## Локальный запуск

### Требования

- Node.js 22 или новее;
- npm;
- backend, доступный на `http://localhost:8080`.

### Установка

```bash
git clone <repository-url>
cd frontend
npm ci
```

Создайте локальный файл окружения из примера:

```bash
cp .env.example .env
```

Минимальная конфигурация:

```env
VITE_BASE_URL=/api
```

Запустите приложение:

```bash
npm run dev
```

Frontend будет доступен на `http://localhost:5173`.

В dev-режиме Vite:

- проксирует `/api/*` на `http://localhost:8080` и удаляет префикс `/api`;
- проксирует `/uploads/*` на тот же backend без изменения пути.

Поэтому локальный backend должен обслуживать API без префикса `/api` и отдавать загруженные файлы по `/uploads/*`.

## Архитектурные особенности

### API и авторизация

Все запросы проходят через единый Axios instance с `withCredentials: true`. При старте приложение вызывает `/auth/me` и восстанавливает пользовательскую сессию. Формы и ответы основных API проверяются Zod-схемами до попадания данных в компоненты.

Для работы frontend ожидает актуальные backend-контракты для авторизации, пользователей, вещей, цепочек, рейтингов, уведомлений, ПВЗ, загрузок, поддержки, жалоб и административных функций.

### Состояние и обновление данных

- React Query отвечает за загрузку, кэширование, polling и обновление серверных данных после мутаций.
- Redux хранит клиентское состояние авторизации, маскота и знакомства с интерфейсом.
- После действий над вещами, обменами, поддержкой и административными сущностями связанные query инвалидируются.

### Жизненный цикл обмена

Основной сценарий использует состояния:

```text
proposed → confirmed → delivering → delivered → completed
```

Отказ участника или административная отмена переводит обмен в `cancelled`. Детальная страница объединяет решения участников, прогресс, чат, ПВЗ, подтверждение получения и форму оценки после завершения.

### Тестирование и CI

Тесты покрывают логику статусов обмена и маскота, представление уведомлений, popup подтверждения, детали обмена и поддержку. Workflow `.github/workflows/frontend-ci.yml` запускает `npm run check` для изменений frontend: строгий ESLint, весь набор Vitest и production-сборку.

## Production

`Dockerfile` собирает приложение в два этапа:

1. образ Node.js 22 выполняет `npm ci` и `npm run build`;
2. Caddy раздаёт содержимое `dist`.

В production Caddy:

- использует SPA fallback на `index.html` для клиентских маршрутов;
- проксирует `/api/*` в сервис `api:8080` со снятием префикса;
- передаёт `/uploads/*` и `/swagger*` в backend;
- сжимает ответы через gzip и zstd;
- использует `SITE_ADDRESS` для адреса сайта, по умолчанию слушая HTTP на порту 80.

Production-конфигурация рассчитана на запуск frontend и backend в общей Docker-сети, где backend доступен по имени `api`.
