# Принудительная отмена обмена администратором

## Зачем это нужно

Администратор может остановить активный обмен, если продолжать его небезопасно или
невозможно. Например, один из участников нарушает правила, а остальные пользователи
не должны ждать завершения такого обмена.

## API

```http
POST /admin/exchanges/{id}/cancel
```

Тело запроса не требуется. В `id` передаётся UUID обмена.

Ручка находится внутри защищённой группы `/admin`. Поэтому запрос должен содержать
действующий токен пользователя, у которого `is_admin = true`.

Успешный ответ:

```http
204 No Content
```

## Что происходит внутри

Отмена выполняется одной транзакцией:

1. Блокируются обмен и все участвующие объявления.
2. Проверяется, что обмен имеет статус `proposed` или `confirmed`.
3. Если обмен уже подтверждён, объявления переводятся из `reserved` обратно в
   `available`.
4. Обмен переводится в `cancelled`, заполняется `closed_at`.
5. После успешной транзакции запускается поиск новых обменов для освободившихся
   объявлений. Точно такой же отменённый состав исключается из повторного поиска.

Административная отмена не считается виной участника. Поэтому она:

- не переводит участника в `declined`;
- не увеличивает `deals_broken`;
- не добавляет пользовательский отказ от конкретной вещи.

## Коды ответа

| Код | Значение |
|---|---|
| `204` | Обмен отменён |
| `400` | Некорректный UUID обмена |
| `401` | Пользователь не авторизован |
| `403` | Пользователь не является администратором |
| `404` | Обмен не найден |
| `409` | Обмен уже закрыт либо состояние объявлений конфликтует с обменом |
| `500` | Внутренняя ошибка сервера |

Для повторной отмены уже закрытого обмена возвращается `409 Conflict`. Это защищает
от повторного освобождения объявлений и делает операцию предсказуемой.
