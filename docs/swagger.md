# Swagger: интерактивная документация API

`docs/users.md`, `docs/items.md` и `docs/auth.md` описывают маршруты словами — их удобно читать, но нельзя
нажать. Swagger добавляет вторую форму той же документации: страницу, где видно каждый
маршрут, его параметры, коды ответов и схемы данных, и где любой запрос можно выполнить
прямо из браузера.

Главное отличие от markdown-доков: спека **генерируется из кода**. Описание живёт
комментариями над самими хэндлерами, поэтому оно физически не может ссылаться на
несуществующий тип — генератор упадёт с ошибкой.

## Как открыть

```bash
make up    # PostgreSQL и миграции
make run   # HTTP API
```

Дальше <http://localhost:8080/swagger/> — путь без слеша тоже работает, он редиректит на
`index.html`. Сама спека доступна как JSON: <http://localhost:8080/swagger/doc.json>.

Адрес сервера в спеку не зашит: UI обращается к тому же origin, с которого открыт. После
деплоя на публичный URL Swagger заработает там без правок.

## Что внутри

| Раздел (tag) | Маршруты |
|---|---|
| `users` | `POST /users`, `GET /users/{id}`, `PATCH /users/{id}` |
| `items` | `POST /items`, `GET /items/{id}`, `PATCH /items/{id}`, `DELETE /items/{id}`, `GET /categories` |
| `auth` | `POST /auth/login`, `POST /auth/logout`, `GET /auth/me` |
| `system` | `GET /health` |

Для каждой операции показаны название, описание, тело запроса, все коды ответа и схема
данных для каждого кода. Схемы (`dto.UserResponse`, `dto.ErrorResponse` и остальные) —
это те же самые структуры из `internal/*/dto`, которые API реально отдаёт.

## Как проверить защищённый маршрут

Кнопки «Authorize» на странице нет, и она не нужна. Аутентификация в проекте построена на
HttpOnly cookie (см. `docs/auth.md`), а такую cookie ставит и отправляет сам браузер:

1. Откройте `POST /auth/login` → **Try it out** → впишите nickname и password → **Execute**.
   В ответе придёт `Set-Cookie: access_token=...`, браузер её сохранит.
2. Теперь выполните `GET /auth/me` или `PATCH /users/{id}` — cookie уедет с запросом
   автоматически, потому что Swagger UI отдаётся с того же адреса, что и API
   (`credentials: same-origin` в его fetch-запросах).
3. `POST /auth/logout` удаляет cookie — после него защищённые маршруты снова отвечают 401.

Если пользователя ещё нет, сначала создайте его через `POST /users`.

## Как перегенерировать

Спека собирается из аннотаций и **коммитится в репозиторий** — иначе проект не соберётся
у того, кто не ставил генератор.

```bash
go install github.com/swaggo/swag/cmd/swag@latest   # один раз
make swagger                                        # после правок в хэндлерах
```

Перегенерировать нужно, когда изменились маршруты, поля DTO или коды ответов. Забыли —
код и спека разъедутся молча, поэтому лучше делать это в том же коммите, что и правку
хэндлера.

Результат кладётся в `docs/swagger/`: `docs.go` (его импортирует `cmd/api/main.go`),
`swagger.json` и `swagger.yaml` — последние можно скормить генератору клиента для фронта.

## Как добавить описание новому хэндлеру

Комментарий перед функцией-обработчиком, пример из `internal/user/handler/handler.go`:

```go
// @Summary     Получить пользователя по ID
// @Description Публичный профиль: рейтинг и счётчики сделок. Аутентификация не нужна.
// @Tags        users
// @Produce     json
// @Param       id  path     string                true "UUID пользователя"
// @Success     200 {object} userdto.UserResponse  "Профиль пользователя"
// @Failure     404 {object} userdto.ErrorResponse "Пользователь не найден"
// @Router      /users/{id} [get]
```

Тип пишется через **тот же алиас импорта**, что используется в файле (`userdto`, `authdto`).
Полный путь пакета генератор не понимает.

## Границы решения

Генератор — [swaggo/swag](https://github.com/swaggo/swag) версии 1, UI —
`swaggo/http-swagger/v2`, вшитый в бинарь (интернет для открытия страницы не нужен).
go-swagger, предложенный в issue, не подошёл: он либо генерирует сервер под свой рантайм
вместо chi, либо требует объявлять типы-обёртки на каждый эндпоинт.

Отсюда два ограничения, о которых стоит знать:

- Формат спеки — **Swagger 2.0**, не OpenAPI 3. Версия swag с OpenAPI 3.1 существует, но
  готовый UI-хэндлер читает реестр только первой версии.
- В Swagger 2.0 нельзя объявить cookie как схему авторизации, поэтому в спеке её нет —
  требование cookie написано словами в описании защищённых операций.
