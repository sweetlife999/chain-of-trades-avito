### Поиск цепочек обмена

Это моя самая крупная часть проекта.

- Написал SQL-поиск совместимых объявлений.
- Представил объявления как вершины направленного графа.
- Реализовал DFS с возвратом назад для поиска замкнутых цепочек от 2 до 5 человек.
- Запретил повторять одну вещь или одного владельца внутри цепочки.
- Преобразовал найденный цикл в понятный состав: кто что отдаёт и получает.
- Сделал транзакционное сохранение обмена и всех его участников.
- Добавил API для получения списка обменов и одного обмена по ID.
- Подключил автоматический поиск после создания и изменения объявления.

Первый рабочий вариант вошёл в
[PR #22](https://github.com/sweetlife999/chain-of-trades-avito/pull/22).

### Несколько обменов и асинхронный поиск

Изначально DFS останавливался на первом цикле. Я переделал его так, чтобы пользователь
получал несколько разных вариантов.

- DFS продолжает обход после первого найденного цикла.
- Собирается расширенный список кандидатов, из которого сохраняются лучшие варианты.
- Поиск работает в фоне и не задерживает создание объявления.
- Очередь не добавляет несколько одинаковых задач для одной вещи.
- Worker обрабатывает ошибки, делает повторные попытки и корректно завершает работу.
- Варианты ранжируются по рейтингу участников, надёжности, опыту и длине цепочки.

### Защита от повторов и сложных ошибок

Во время тестов несколько раз находились ситуации, когда одинаковые обмены создавались
параллельно или старый запрет мешал найти хороший обмен. Я последовательно исправлял эти
сценарии.

- Добавил каноническую подпись обмена.
- Добавил отдельный ключ точного набора объявлений.
- Сделал уникальность только для активных обменов, чтобы закрытый обмен не запрещал
  комбинацию навсегда.
- Добавил блокировки строк вещей перед сохранением.
- Защитил создание от двух параллельных DFS.
- Запоминаю точный состав сорванного подтверждённого обмена, чтобы он не повторился.
- При этом обмен с заменой хотя бы одной вещи снова может быть найден.

PR: [#51](https://github.com/sweetlife999/chain-of-trades-avito/pull/51),
[#103](https://github.com/sweetlife999/chain-of-trades-avito/pull/103). Также исправлен
сценарий из [issue #55](https://github.com/sweetlife999/chain-of-trades-avito/issues/55).

### Полный жизненный цикл обмена

- Сделал ручки `confirm`, `decline` и `complete`.
- Обмен подтверждается только после согласия всех участников.
- После подтверждения вещи резервируются.
- Другие предложения с занятыми вещами отменяются.
- Получение подтверждает каждый участник отдельно.
- После подтверждения всех обмен завершается, а статистика пользователей обновляется.
- После отмены вещи освобождаются и поиск запускается повторно.

Позже добавил разные причины отмены. Backend теперь понимает разницу между отказом от
неподтверждённого предложения и срывом уже подтверждённого обмена. От этого зависит
статистика пользователя и то, какие обмены можно предложить снова.

PR: [#34](https://github.com/sweetlife999/chain-of-trades-avito/pull/34),
[#37](https://github.com/sweetlife999/chain-of-trades-avito/pull/37),
[#111](https://github.com/sweetlife999/chain-of-trades-avito/pull/111).

### Управление поиском пользователем

- Сделал список заблокированных пользователей: добавить, посмотреть и убрать блокировку.
- Научил DFS не объединять заблокировавших друг друга пользователей.
- Добавил возможность снять своё объявление с поиска.
- При снятии связанные предложения отменяются, но подтверждённую сделку сломать таким
  способом нельзя.
- Объявление можно вернуть в поиск, после чего DFS запускается снова.
