# ПВЗ в административной панели

ПВЗ — место, куда пользователи приносят и откуда забирают вещи. Сейчас администратор
может создавать, смотреть, изменять и удалять ПВЗ. Обычным пользователям эти ручки
недоступны.

## Данные ПВЗ

- `id` — UUID ПВЗ;
- `name` — название длиной до 120 символов;
- `address` — адрес длиной до 500 символов;
- `created_at` — время создания;
- `updated_at` — время последнего изменения.

Название и адрес обязательны. Перед сохранением backend убирает пробелы по краям.

## Ручки

Все ручки находятся под `/admin`, поэтому сначала проверяются авторизация и право
администратора.

| Метод и путь | Что делает |
|---|---|
| `POST /admin/pickup-points` | Создаёт ПВЗ |
| `GET /admin/pickup-points` | Возвращает все ПВЗ от новых к старым |
| `GET /admin/pickup-points/{id}` | Возвращает один ПВЗ |
| `PATCH /admin/pickup-points/{id}` | Меняет название и/или адрес |
| `DELETE /admin/pickup-points/{id}` | Удаляет ПВЗ |

Основные коды ответа:

- `401` — пользователь не вошёл в аккаунт;
- `403` — пользователь вошёл, но не является администратором;
- `404` — ПВЗ с таким ID не существует;
- `409` — ПВЗ используется объявлениями, поэтому удалить его нельзя.

## Архитектура

- handler читает HTTP-запрос и формирует HTTP-ответ;
- service очищает и проверяет название и адрес;
- repository вызывает сгенерированные sqlc-запросы;
- PostgreSQL хранит данные и не позволяет удалить используемый ПВЗ;
- Swagger описывает контракт для фронтенда.

Привязка объявления к ПВЗ не входит в этот модуль: она добавляется отдельной задачей,
чтобы не смешивать CRUD справочника ПВЗ с изменением модели объявления.
